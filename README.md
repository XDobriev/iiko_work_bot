# 🧾 iiko Work Bot (v2.0 TypeScript) — Бейни

Интеллектуальный Telegram-бот для ресторана **Бейни** для автоматического распознавания рукописных накладных и товарных чеков с помощью **Google Gemini 3.8 Flash Vision**, локальной базы данных **SQLite** с исторической памятью цен и интеграцией в **iikoWeb** (создание приходных накладных-черновиков).

---

## 🌟 Ключевые возможности

1. **Распознавание рукописного текста (Gemini 3.8 Flash Vision):**
   * Точное извлечение наименований позиций, количества, цен, сумм и написанного от руки итога.
   * Автоматическое распределение по складам: **Склад Кухня** (продукты) или **Хоз склад** (бытовая химия, перчатки, салфетки, упаковка).

2. **🎙 Распознавание голосовых сообщений:**
   * Шеф-повар или закупщик может не фотографировать, а надиктовать голосом в Telegram:  
     *«Бойня привезла 15 кг говядины по 620 рублей на кухню и 5 пачек салфеток по 100 на хоз склад»*.
   * Gemini 3.8 Flash напрямую слушает аудио и формирует структурированную накладную!

3. **🔄 Интерактивное переключение склада:**
   * Кнопка **`[🔄 Склад: Кухня ⇄ Хоз]`** позволяет в один клик изменить склад перед отправкой в iiko, если нужно перенаправить позиции.

4. **🖼 Локальный архив оригиналов фото:**
   * Каждое фото сохраняется локально в папке `data/photos/`.
   * Кнопка **`[🖼 Фото]`** позволяет в любой момент открыть и сверить исходный рукописный чек прямо в Telegram.

5. **📊 Сверка цен и защита от переплат (Price Intelligence):**
   * Бот помнит историю цен на каждый ингредиент и сравнивает с прошлой закупкой.
   * Предупреждает о подорожании:  
     `🔺 Говядина мякоть: 600 ₽ (+50 ₽ / +9.1% к 15.10.2026)`
   * Фиксирует скидки (`🔻`) и новые позиции (`🆕`).

6. **📁 Выгрузка для бухгалтера и Excel (`/export`):**
   * Команда `/export` формирует готовый CSV-файл с кодировкой UTF-8 BOM, который сразу открывается в Excel без кракозябр.

7. **📈 Ежедневная сводка (`/today`):**
   * Сумма расходов за день с разделением на Кухню и Хоз склад.
   * Список всех поставщиков за день и сумм закупок.

8. **Интеграция с iikoWeb (`beyni.iikoweb.ru`):**
   * По кнопке **`[✅ Создать в iiko]`** в iikoWeb создается **приходная накладная в статусе «Черновик»**. Проводит её человек в iikoWeb: *«Управление складом» ➔ «Документы»*.
   * Если пароль от iiko не указан — бот автоматически работает в **демо-режиме**, не блокируя работу.
   * Подробности, формат запросов и результаты проверки — в разделе [Интеграция с iikoWeb](#-интеграция-с-iikoweb) ниже.

### Как это устроено

Клиент — [src/iiko/client.ts](src/iiko/client.ts). Работает через внутренний API iikoWeb (тот же, что использует интерфейс), браузер не нужен. Официальной документации на создание накладных у этого API нет, адреса и формат запросов получены наблюдением за интерфейсом, поэтому после обновления iiko они могут измениться.

Порядок запросов при отправке накладной:

1. `POST /api/auth/login` — вход, тело `{"login","password"}`.
2. Справочники: `GET /api/documents/suppliers/list`, `/api/documents/storage/list`, `/api/documents/product/short_list`, `/api/documents/conception/list`, `GET /api/stores/list`.
3. `POST /api/documents/product/ids` — тело: массив id товаров, ответ: шаблоны позиций (единица, фасовка, код).
4. `POST /api/documents/create` — шапка документа: `type: INCOMING_INVOICE`, `status: DRAFT`, `supplier`, `storage`, `store`, `conception`, `dateIncoming`. Ответ: `id` и номер документа.
5. `POST /api/documents/save/{id}` — шапка + `items` (количество, цена, сумма).
6. `GET /api/auth/logout` — освобождение сессии.

Другие полезные адреса:

* Чтение документа: `GET /api/documents/get/{id}?type=INCOMING_INVOICE`.
* Список документов: `GET /api/documents/list?dateFrom=...&dateTo=...&store=...`.
* Удаление: `POST /api/documents/update_status/{id}` с телом `{"status":"DELETED","type":"INCOMING_INVOICE"}`.
* Проведение в интерфейсе — кнопка «Провести». Какой запрос она отправляет, ещё **не изучено**: нужно посмотреть во вкладке Network при проведении тестового документа.

### Правила сопоставления

* **Поставщик** ищется по названию (точное совпадение, затем по вхождению). Не найден — накладная не создаётся.
* **Склад:** «Кухня» ➔ склад, в названии которого есть «кухн»; «Хоз» ➔ «хоз». Если не найден, берётся первый склад.
* **Товары** ищутся по названию без служебных меток вроде `|ПФ|` и `*`. Не найденные позиции в накладную не попадают.
* **Единица измерения** берётся основная из карточки товара в iiko, а не из распознанной накладной. Количество передаётся в этой единице.
* **Дата** документа ставится на 09:00 по московскому времени (`+03:00`).

### Известные особенности

* Сервер iikoWeb отвечает ошибкой 500 на заголовок `Accept-Language: *`, который Node подставляет по умолчанию. Клиент всегда отправляет `Accept-Language: ru-RU` (константа `BASE_HEADERS`).
* Сессия iikoWeb живёт около 20 минут, клиент обновляет её сам.
* В `.env` должна быть одна строка `IIKO_PASSWORD`: при дублях значение берётся из последней.
* Для бота рекомендуется отдельный пользователь iiko только с правами `DOCUMENT_BUNDLE_INCOMING_INVOICE_VIEW` и `DOCUMENT_BUNDLE_INCOMING_INVOICE_CREATE_AND_EDIT_DRAFT` (без права проведения). Сейчас используется учётная запись администратора.
* `npm run test:pipeline` не отправляет данные в iiko, если задан `IIKO_PASSWORD`. Реальная отправка (создаст черновик) — только при `IIKO_TEST_SEND=1`.
